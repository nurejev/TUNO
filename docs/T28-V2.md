# T28 V2 — volledige tweede werkruimte binnen TUNO

> **Sinds build 10661 is V2 de enige T28.** De oorspronkelijke controller ("Existing"), de versieschakelaar (`js/t28v2.js`) en de engine-kopie in `js/mderolloutv2.js` zijn verwijderd. V2 (`MdeRolloutV2Tool`) draait op de gedeelde engine `MdeRollout` in `js/mderollout.js`, die `js/mdeasr.js` en `js/mdemembers.js` ook gebruiken. Opgeslagen naming rules van het oude scherm (`tuno.t28.rules.<tenant-id>`) worden één keer overgenomen wanneer V2 voor die tenant nog geen eigen regels heeft; het Naming rules-paneel meldt dat en de oude sleutel wordt nooit beschreven. De regressiesuite van het oude scherm (277 checks) is overgezet naar V2 in `tests/mderollout/screen.test.js` en slaagt volledig, met de V2-poorten (risicobesluit, groepsbackup) beantwoord waar een plan erom vraagt. Er ontbrak dus geen functie in V2. De tekst hieronder beschrijft de oplevering van 10660.

Build **10660**, T28 **0.27**, gebaseerd op commit `137894062db68f2b06878c018eebc3c9e90a4ee8` (build 10659).

Open T28 en kies **V2 · guided rollout** naast **Existing**. Beide werkruimtes staan op dezelfde pagina, gebruiken dezelfde aanmelding en dezelfde Graph-client. Er is geen tweede URL, redirect URI of appregistratie nodig. De bestaande T28-controller en de gedeelde Graph-engines zijn ongewijzigd. V2 is een zelfstandige kopie van de volledige T28-controller en vergelijkingsengine, met eigen DOM, plannen, instellingen en sessiehistorie.

## Wat werkt

Alle huidige T28-functies blijven beschikbaar in V2: policies vergelijken, nieuwe en oude policies, retirement checks, wavegroepen maken en hernoemen, rollouttoewijzingen, members, pilots, exclusions, ASR-modi wijzigen, rapporten, exports en sessie-undo. Schrijfacties gebruiken de bestaande Graph-koppeling en scope-toestemming.

Toegevoegd:

- Overzicht met zes stappen en duidelijke verwijzing naar de juiste werkruimte. Ongelezen membership en onbewezen devicebescherming blijven onbekend.
- Navigatie gegroepeerd op voorbereiden, uitrollen en controleren; responsieve kaarten en navigatie voor kleinere schermen.
- Eigen per-tenant naming rules: `tuno.t28.v2.rules.<tenant-id>`. In 10660 begon V2 met de standaardregels; sinds 10661 nemen ontbrekende V2-regels één keer de opgeslagen regels van het oude scherm over. Controleer Naming rules vóór de eerste rollout.
- Een plan wordt gebonden aan de tenant, V2-regels en ASR-scopebeslissing. Nieuwe context vereist een nieuw plan.
- Oude assignments verwijderen of uitsluiten vereist bij onvolledige retirementdekking of onbewezen assignmentbereik een expliciete risicoacceptatie met reden van minimaal 20 tekens.
- Verlaging van ASR-enforcement en de expliciete Leave out-uitzondering vereisen eveneens een vastgelegde reden en acceptatie.
- ASR-policies met Leave out zijn standaard vergrendeld. De uitzondering is een zichtbare opt-in voor de huidige sessie; veranderen wist ASR-edits en het plan.
- Members, pilottransities en exclusion-membershipplannen vereisen nu ook een download van het groepsbackupbestand. De geraakte directe memberships worden bij het maken van het plan gelezen, voor de backup gecontroleerd en vlak vóór toepassen opnieuw gecontroleerd. Afwijking of leesfout blokkeert schrijven.
- Alleen bevestigde memberwijzigingen veranderen het getoonde model. Onzekere of gedeeltelijke writes wissen membership-readiness en vereisen opnieuw lezen. Undo neemt alleen bevestigde werkelijke verschillen mee en haalt geen reeds bestaande membership/nesting weg.
- Run files exporteert regels, tenant-ID, backups, schrijfresultaten en risicoacceptaties naar JSON. Import controleert schema en tenant en toont het dossier zonder schrijven of regels te veranderen.
- (Alleen 10660) Versieschakelen bewaarde beide werkruimtes maar wiste open plannen. Vervallen in 10661: er is geen schakelaar meer.

## Grenzen van deze beta

De code is getest met headless integratietests en gesimuleerde Graph-antwoorden, inclusief schrijven en sessie-undo. Er is geen live tenant-acceptatietest uitgevoerd. Er zijn geen cloudconfiguraties gewijzigd tijdens het bouwen van deze patch.

Automatisch herstel uit een geïmporteerd bestand na herladen is nog niet geïmplementeerd. Sessieruns hebben de bestaande undo-flow, met een nieuw plan en bevestiging. De importfunctie is een inspectie van het geëxporteerde dossier. Onzekere writes moeten eerst door een fresh read en gerichte reconciliatie worden vastgesteld.

Groepsbackups bevatten de directe memberships van de geraakte membertypen, plus de voorgenomen operaties; ze zijn geen volledige tenantbackup. Group create en rename behouden hun bestaande bevestigingsflow. Device mapping gebruikt de bestaande bewijslijnen en heuristieken; een nieuwe handmatige mapping-reviewworkflow is niet toegevoegd. Geen status op het overzicht bewijst dat een device de policy heeft toegepast.

Een gedownloade backup ontgrendelt Apply wanneer de browser de download start. Controleer dat het bestand werkelijk is opgeslagen. JSON en Markdown worden als echte bestanden gedownload; op iPad kan de client het bestand als preview openen. Het distributiebestand is daarom een ZIP met een echte downloadlink. Open zo nodig de link in Safari en bewaar via Delen → Bewaar in Bestanden. Downloadfouten kunnen zonder foutmelding/screenshot niet exact worden vastgesteld.

## Installeren

De download bevat één `t28-v2-10660.mbox` en installers voor PowerShell en bash. Uitpakken gebeurt buiten de repo. De installer controleert Git, een schone werkboom, exact de basiscommit, afwezigheid van een lopende Git-operatie en de checksum. Hij maakt een lokale branch, past de patch toe en pusht niets.

Windows, vanuit de uitgepakte download:

```powershell
powershell -File .\install.ps1 -Repository "C:\pad\naar\tuno-beta"
```

macOS / Linux:

```bash
bash install.sh /pad/naar/tuno-beta
```

Handmatig, alleen op de genoemde basiscommit:

```bash
git switch -c beta/t28-v2-10660
git am /pad/naar/t28-v2-10660.mbox
```

Als je repo morgen verder is dan de basiscommit, stopt de installer bewust. De patch moet dan tegen die nieuwe tip worden bijgewerkt en de build opnieuw genummerd. Forceer de patch niet en reset je werkboom niet. Je kunt de versie wel los onderzoeken via een worktree op de basiscommit:

```bash
git worktree add ../tuno-t28-v2-review -b beta/t28-v2-review 137894062db68f2b06878c018eebc3c9e90a4ee8
bash /pad/naar/install.sh ../tuno-t28-v2-review
```

## Uitvoeren en controleren

TUNO blijft statische HTML/CSS/JavaScript zonder buildstap. Publiceer de gewijzigde repo via je bestaande route, of serveer hem lokaal volgens je bestaande aanmeldconfiguratie. Gebruik geen `file://` voor Graph-aanmelding. De patch wijzigt je hosting of appregistratie niet.

```bash
npm install --ignore-scripts --no-audit --no-fund
npm test
```

Open T28 → V2 → Read the tenant. Controleer de Naming rules en voer eerst een beperkt plan uit. Existing blijft direct beschikbaar. Na een live run: exporteer Run files en controleer Intune/Defender-devicebewijs. Undo van V2-runs staat onder Changes this session.

## Bestanden en onderhoud

| Bestand | Functie |
| --- | --- |
| `js/mderolloutv2.js` | Volledige zelfstandige T28-engine en controller; eigen DOM-prefix `mv` |
| `js/t28v2safety.js` | Membershipsnapshots, driftcontrole, verified/actual deltas en importvalidatie |
| `js/t28v2.js` | Schakelaar, shared screen hook en blokkering tijdens actieve acties |
| `css/t28v2.css` | V2-kaarten, navigatie, risk gates en responsive layout |
| `tests/t28v2/` | Engine-, safety- en workspace-integratietests |

De gedeelde member-, assignment-, ASR- en Graph-engines blijven gemeenschappelijk. Toekomstige wijzigingen in die dependencies moeten tegen beide T28-workspaces worden getest. De V2-controller is een expliciete fork en volgt wijzigingen in de originele controller niet automatisch. Releaseboekhouding en de PowerShell-buildstempels zijn naar 10660 verhoogd; de PowerShell-scriptlogica verandert niet.

Terug naar de bestaande UI: kies Existing. De hele patch terugdraaien: `git revert <de-patch-commit>` op een schone branch. Een code-revert draait reeds uitgevoerde tenantwijzigingen niet terug; daarvoor gebruik je de gecontroleerde undo-flow en backups.
