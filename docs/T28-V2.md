# T28 — MDE rollout project

Build **10692**, T28 **0.42**, beta / Workspace 02 Projects.

T28 opens as a project cockpit. It automatically attaches the sign-in policy read (or reads policies if none is available), then reads country membership and return holds, exclusions and Windows inventory, policy check-in status and device conflicts. Reads use existing permissions silently. When consent is missing, **Connect data** is an explicit action; failed and partial reads remain visible in **Data details**.

## Where to work

| Area | Functions |
| --- | --- |
| Overview | Country / pilot scope, policy and verification counts, source status, attention list with links to evidence |
| Waves | Country workspace, membership and pilots, country sync, wave groups and test members, verification |
| Policies | New / old policies and assignments, conflicts, ASR settings, Edge extensions, retirement, out-of-scope policies |
| Exceptions | Exclude from new policies; return to old / resume rollout; single and bulk workflows |
| Journal | Browser history, session changes and undo, four reports, run files and recovery |
| Project setup / Help | All existing naming rules, scope, device placement, pilot and lookup settings, workflow explanation |

Inside a country workspace, **Members, Policies, Verification, Exceptions and Evidence** provide the local context. Policies assigned to a shared wave still affect that whole wave; the country selection does not narrow an assignment edit. Exceptions link to the project-wide review. Verification matches members by immutable IDs, including proposed country scope, and labels absent evidence explicitly.

## Read and report behaviour

The initial automatic sources run in sequence and are attempted once. **Refresh project** retries them. Opening the same tool again retains the current read; there is no timer polling. Data details records each source's read time and problems. Changes made after a source read are marked. Device check-in time is separate from when T28 read the report.

Navigation stays available during reads. An active write or a prepared change plan prevents background report generation and further queued reads. Signing out invalidates pending automatic responses. No automatic read applies a tenant change.

Reports are under **Journal → Reports**: Assignments, Deployment configuration, Conflict check and Landing check. A preview is prepared automatically when selected, retaining its HTML and CSV exports. Reports that predate changed source data are regenerated when opened. An explicit conflict check still performs a fresh policy and device read and compares it with earlier checks in the session. The automatic conflict preview uses the current project evidence.

## Exclusion, return and resume

- **Exclude from new** uses the configured user/device policy exclusion groups. With keep-old selected, device country membership can also be removed. Old targeting and other assignment routes still need review.
- **Return** adds the selected members to return-hold groups and removes their mapped static country memberships. These hold groups stop later country sync from automatically placing them back. A return does not prove that old protection is active.
- A **device** return starts with that device only. Its primary user is shown but requires an explicit tick. A **user** return retains the user-and-recent-devices selection. Multiple devices owned by the same user remain separate bulk entries.
- **Resume** is a separate dry run: remove the hold and restore the selected country memberships. Existing reason, count/wave confirmation, backup and verified-step requirements remain.

Review policy targeting, perform the reviewed group change, then examine device check-in evidence and the actual outcome. Assignment or successful group membership alone is not functional protection proof.

## Change and recovery contract

All existing operation panes use the existing engines. The single plan panel survives navigation. Policy reads and group snapshots, backup downloads, typed removal confirmation, recorded risk decisions, tenant/config binding, drift detection, dependent steps, verification, stop controls and session undo remain in place.

**Project history** saves the last 100 run summaries per tenant in this browser. It is a browsing aid, not a durable server audit log. Full backups and executable undo remain in the session; exported run bundles retain recovery evidence. Importing a saved run bundle is review-only and does not reconstruct executable undo after reload. Download run files before leaving if recovery evidence is needed elsewhere.

## Compatibility and validation

`MdeRolloutV2Tool` remains the only T28 controller and uses the shared `MdeRollout` engine. Existing tenant settings, pilots, pins, skip lists, extension names/lists and reasons keep their storage keys. Naming rules from the old T28 key are still carried over once if the current key does not exist. Existing feature IDs remain available for the operation handlers.

The complete feature mapping and validation record are in [T28-beta-10692.md](reviews/T28-beta-10692.md). Local demo tests do not establish live tenant consent, role access, propagation or endpoint behaviour.
