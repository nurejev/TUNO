# T01 deployed policy reader fix — beta 10630

Date: 2026-09-29. T01 1.0.74.

## Report and cause

Clicking the deployed Audit policy in 10629 displayed the generic error “Each Audit setting must contain exactly one readable RuleCollection” instead of opening results. That guard conflated malformed XML, an unread encrypted value and supported alternate XML representations. The screenshot alone does not establish which returned value affected the live profile; no live profile value was available during this fix.

## Changes

- Shared profile parsing accepts a bare RuleCollection, XML declaration/BOM, a Version 1 AppLockerPolicy wrapper with exactly one collection, and UTF-8 base64 XML-file settings. Ambiguous multi-collection wrappers and unsupported XML remain rejected.
- T01 opts into forced plaintext retrieval for encrypted settings even when the list or single-object response includes a non-empty placeholder. Other hydration consumers retain their existing behavior. A detail read still supplies missing secret references; the placeholder cannot stop the following plaintext request.
- Audit updates preserve the original XML-file setting type, filename, wrapper shape and Unicode content. The original hydrated profile remains available for backup.
- Reading shows progress and prevents competing selection. Failures name the selected profile and affected setting; decryption failures retain their cause. The list action is now “Open policy for review”, since mode is verified from values after reading rather than inferred from the profile name. Successful reads restore enabled suggestion controls and open results.

Microsoft documents XML-file values as binary UTF-8 data: [omaSettingStringXml](https://learn.microsoft.com/en-us/graph/api/resources/intune-deviceconfig-omasettingstringxml?view=graph-rest-1.0).
