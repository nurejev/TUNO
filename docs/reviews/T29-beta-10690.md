## Delivered

- Policy workspace with editable full XML and individual rule XML; import the two supplied R27.1 templates, upload XML, undo, explicitly change mode, add a reviewed publisher allow, and export.
- Non-DLL XML normalization preserves the retained rule IDs, conditions and exceptions. Templates are bundled copies; the original source files were not changed.
- Microsoft app coverage uses T01's catalog and matcher, with conditional labels for uncertain version/hash/group cases. The optional OneDrive publisher rule is a deliberate edit.
- Weekly results accept T29 Harvest and existing T01 event bundles. Application scan bundles are refused. Events are filtered for DLL and deduplicated across imported windows. Device identity, stale/partial evidence, window and selected MDM collection receipts are shown. Unread evidence and the unknown assigned-fleet denominator are explicit.
- New Intune profiles start unassigned with one automatically generated grouping, stable across XML/mode edits. Assignment to an exact security group is a separate reviewed action.
- Existing profile redeployment preserves its immutable ID, grouping, setting types/encoding, unrelated settings, collection node set and assignments. Readable values, fresh snapshots, rollback download, drift/collision checks, deliberate enforcement review and read-back are required. Existing DLL or multi-grouping profiles require migration. A successful Intune write is not device enforcement proof.
- Unknown policy/helper write outcomes remain pending and can be resolved by reads without replaying the write. Definite authorization/request rejections allow a fresh explicit attempt. Sign-out discards old in-flight responses and clears session data/credentials.
- Clear AppLocker v1.4.0 and Collect AppControl Events v1.3.1 are carried over. Existing helper updates preserve assignments/schedules and require a rollback export. New helpers start unassigned. Both scripts can be downloaded together as one ZIP.
- Dedicated weekly detector and collector v1.0.0: use a Daily Intune schedule, with seven days since the last successfully uploaded collection controlling when work is due. Pending uploads retry unchanged. Only existing AppLocker events and policy receipts are read; no application inventory or ACL scan. Local/GPO and MDM sources remain separate.
- Upload receipt and size read-back precede checkpoint commit. Only exact T29 file names in this device's history are pruned after delivery; the latest cloud copy and pending local queue are retained. Default retention is 30 days, with 0 keeping history. Certificate authentication is preferred; a configured secret is included in the deployed script.

## Source XML findings

Both filenames contain four **Enabled** retained collections; the Audit filename does not mean AuditOnly. Each retains 27 rules after omitting 40 DLL rules. The retained collections contain 119 exception conditions.

The T01 catalog predicts **10/11 allowed**, with per-user OneDrive blocked. Adding the dedicated Microsoft OneDrive publisher allow predicts **11/11 allowed**. This does not establish installed version coverage or functional behavior on a device.

The supplied policies also have unrestricted defaults overlapping exception-bearing rules, unsupported `%PROGRAMDATA%` path macros and IT-TOOLS folder paths without a subtree wildcard. These remain visible findings; they were not silently rewritten. Broad signed Appx and Defender path allowances remain policy review decisions. Administrators must record the disposition of any catalog gaps before an enforced deployment, or use AuditOnly while testing.
