# T28 MDE rollout — beta 10636

Date: 2026-09-29. T28 0.5. Queue item 198.

## Why

Mihai: "PVM-DG-MDE-Exclusion and PVM-UG-MDE-Exclusion should be INT-SG-D-MDE-Exclusion and INT-SG-U-MDE-Exclusion."

This follows 10635, which renamed the wave groups to `INT-SG-D/U-WAVE-<region>`.

## What changed

- **Defaults.** The exclusion groups are now `INT-SG-D-MDE-Exclusion` and `INT-SG-U-MDE-Exclusion`.
- **Saved configs.** A config saved in the browser with the old default names moves to the new ones. A name typed by hand stays.
- **Old names are still found.** `renameExclusionFrom` holds the old defaults, plus any exclusion name changed under ⚙️. Each exclusion group carries its `oldNames`, and the lookup asks for them.
- **Rename in the 🌊 pane.** A group found only under its old name shows as "old name" and is renamed together with the waves, using the same `renameGroup` as 10635:
  1. It checks that the new name is free.
  2. It PATCHes the display name and mail nickname.
  3. It reads the group back.

  The object id does not change, so every assignment, exclusion and nesting stays as it is. 📜 renames the group back.
- **Wave members.** The `INT-SG-D-` device-group read now skips every rollout group name (waves, exclusion groups and their old names), so none of them is counted as a country device group.

## Validation

- **Tracked suites: all 16 pass.**
  - `mderollout/engine`: 175.
  - `mderollout/screen`: 114. In demo, the user exclusion group sits under its old name. It is renamed with the Americas device wave, read back on the same ids, and renamed back from 📜.
- **Scratch suites:** unchanged against the baseline. `sidenav-tests` was already red before this build.
