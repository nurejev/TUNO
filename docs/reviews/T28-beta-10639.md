## ⊘ Exclusions (new `js/mdeexclude.js`, DOM-free)

| Part | What it does |
| --- | --- |
| Header button | **⊘ Exclude user or device**, shown once the tenant is read. It opens the ⊘ rail pane with the cursor in the search. The first open reads both exclusion groups (direct members) and every Windows device in Intune (primary user, Entra device id). |
| Rail node | Shows `users · devices`, or **N half** in red. |
| Search | **Users:** Graph `$search` on `displayName`, `userPrincipalName` and `mail`, with `ConsistencyLevel: eventual`. Per Learn, each clause is quoted and a `"` or `\` inside is escaped.<br>**Devices:** Entra `$search` on `displayName`, plus a local match on the Intune list, so part of a name (`0412`) or a UPN finds it. Entra's tokenizer would miss it.<br>Enter searches. |
| The card | **A user** comes with their Windows devices by Intune primary user.<br>**A device** comes with its primary user, and that user's other devices are shown.<br>Each device's Entra object is read by `devices(deviceId='…')`, because a group member is the object. The card also reads the transitive groups (user and device) and the device's direct groups. It shows the country group, the wave, stale devices, and devices that cannot be members (no Entra object, not joined). |
| What reaches them | Per object: in-scope new and old policies whose groups include it (or All devices / All users of its kind) and exclude none of its groups. An exclusion wins over an include of the same kind (Learn: include/exclude assignments). Filters are not evaluated; a filtered include is labelled. Shown **before** and **after the run**. |
| Default ticks | Picking a user ticks the user and every device that synced within `staleDays` (30). Picking a device ticks only that device, so a lab machine's user is left alone. |
| The run | Through 👥's plan and ledger (`MdeMembers.applyOps`), in order:<br>1. user → user exclusion group<br>2. devices → device exclusion group<br>3. out of their country device group<br>It is an addition, so it is confirmed with a tick. Read-back is **by member kind** (users are read back as users; before this build the read-back assumed devices). The plan opens under the card. Undo is from 📜 (typed REMOVE). The lists move with the run, and the card is read again. |
| Excluded now | Both groups as pairs:<br>- **half**: the user is excluded but a recent device is not, so the `- D -` policies still reach it. There is a **+ add device** button.<br>- **device only**: the user is not excluded, or there is no user.<br>Rows can be taken out with a typed REMOVE. A removed device goes back into its country group with the next 👥 sync of that country. |

### Keep it on the old set

⚡③ takes the waves **out** of the old policies. A device in a wave that is also excluded from the new set would get **neither**. It would have no Intune AV/ASR policy, only Defender's defaults. I found this while drawing the mockup, and Mihai picked *keep it on the old set*:

- **Leaving the wave.** An excluded device is also taken out of its direct country device group (`INT-SG-D-<ISO3>`, never a wave or a rollout group). It leaves the wave, and the old device policies reach it again. The card shows this before the write.
- **👥 keeps it out** (`MdeMembers`):
  - `readInput` reads the device exclusion group.
  - `compute` never wants a held device and offers to remove it if it is in: "(excluded)", `problems.held`.
  - The device detail says "⊘ excluded — kept out, on the old set".
- **A user cannot leave** a dynamic country group. If an excluded user falls between the sets for the `- U -` policies, the card says so.

The exclusion groups can be the new names or still the old names. Whichever the 🌊 pane found is used.

## ⚙️ Leave out of the target list

- **The box.** An exact-name list sits beside "Also in". It uses the same name folding: dashes, spaces and case.
- **Scope.** A name in it is `out` whatever its prefix or content:
  - it is listed under 🚫 with **➖ left out by name**;
  - it is never compared or planned;
  - it is never pulled in by a shared setting;
  - it adds no settings to the new-set keys.
- **Both lists.** A name in both is left out.
- **Report.** The configuration report's rules table lists it.

## Plans open under the button

- **Where.** The plan panel is still one node for the session. It is now seated **right after the card that made it**, and it shows its progress line there:
  - 🌊's rollout card (`mrRollCard`);
  - the ⊘ card;
  - ⊘ Excluded now.
- **Other plans.** The selection bar, 👥 and 📜 undo plans open under the pane as before.
- **Switching panes.** On another pane the plan sits under that pane, and it comes back to its card when you return.
- **Scrolling.** `scroll-margin-top` keeps its heading clear of the sticky header.
