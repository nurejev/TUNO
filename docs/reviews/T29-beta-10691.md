# T29 P-2715 Applocker & harvest — beta 10691 / v0.2

Restores the approved **Policy workspace** from the 7 October Intune deployment mockup (`t01-intune-deploy.html` in this chat's visualization folder). T29 remains a temporary beta tool in **Workspace 02 · Projects**.

## Confirmed problems

- Build 10690 replaced the mockup's compact navigation, green palette, separate configuration/verification/review panels, field-based rule editor and visible import findings with a generic large form. It opened on weekly results rather than the approved deployment workspace.
- The deployment button considered backup, review and ENFORCE, but the write handler additionally required at least 20 characters in pilot and coverage-disposition notes. The screenshot's `justified` was rejected after the button had been enabled. The reason was rendered in a global status above the form.
- `.btn { display: inline-flex }` overrode the browser's `hidden` presentation, so a recovery action could appear without a pending write.
- A default template read during startup was discarded by the subsequent session reset. Local source loading now occurs when the tool opens.

## Restored behavior

- Compact 155px workflow navigation with a divider, the mockup's scoped light/dark palette, top deployment action, source summary and import notice. Navigation wraps on phones; it does not introduce a new sticky layout.
- Intune configuration, verification and deployment review are separate panels. Operation and deployment mode controls, policy name, grouping/Generate new, Check in Intune, assignment/included collections, stage sequence, policy address preview and recovery are in their approved positions.
- The source XML opens locally as the draft with 40 DLL rules omitted. Its actual enforced modes are retained and disclosed; AuditOnly remains a deliberate edit.
- Rule and XML editor modes, collection/rule selectors, editable name/action/principal/condition fields, save/check actions and a separate two-column import review. IDs, exceptions and unedited XML survive field edits. Unsaved rule edits block deployment review.
- Weekly results show three summary cards, a recommended next action and device evidence. Values use imported evidence and the actual T01 catalog prediction. The assigned fleet denominator remains unknown.
- Harvest setup, collector/carry-over helper cards and helper review/deployment are separate panels. Existing collection cadence, eight-day lookback, retention and helper script behavior are unchanged.
- Button readiness and deployment execution share one validation function. Pilot/gap notes must be nonempty for enforced deployment, with exact ENFORCE, reviewed XML and a downloaded rollback snapshot. There is no arbitrary length threshold.
- Missing requirements appear beside the deployment action; write and other action errors appear in their own workspace area. Errors are brought into view. Recovery controls are hidden by scoped CSS unless a write outcome is pending. Pending state blocks another write.
- Fresh snapshots, collision/drift checks, immutable ID/grouping/assignment preservation, separate exact-group assignment and read-back recovery remain in place.
- Changelog, Help's Waiting for production queue (item 253), roadmap R42, tool version and cache references move together. Companion scripts change only their build headers/stamps, preserving their original encodings and behavior.
