# T28 MDE rollout — beta 10632

Date: 2026-09-29. T28 0.1 (new, temporary). T11 1.0.13. T22 1.0.14.

## Why

Mihai's rollout replaces a tenant's old Defender / endpoint security policies with a new set. The new policies are named `Win - OIB …`, `WIN-SEC-…` or `WIN-DCP-…`; everything else is old. `AVD…` and `WinServ…` are out of scope. The ask: filter those quickly, adjust assignments (include / exclude), find the old policies that conflict with a new one so an exclusion can be added, and create the wave groups (`PVM-UG-MDE-WAVE-Euro`, `-Americas`, `-Asia-Pacific`, `-Italy`, `-BAMSCA`). A temporary tool on tuno-beta.

Layout B was picked off the mockup (`Claude outputs/t28-mde-rollout-mockup.html`): a rail with one pane per job. Conflicts are grouped by the OLD policy, because that is the object an exclusion is written to.

## Decisions grounded in Microsoft Learn

- **User ↔ device group mixing.** *Assign policies in Microsoft Intune*, support matrix: excluding user groups from a policy assigned to device groups (or the reverse) is not supported — "Intune doesn't evaluate user-to-device group relationships, and devices of the included users aren't excluded."
  - The wave groups are USER groups (`UG`), and many old policies target device groups, so this rule decides most proposals.
  - A proposal that mixes the two is shown with its reason and never written.
  - Group kind is read from the dynamic rule, or else from typed transitive `$count`s (users / devices). An empty assigned group falls back to its name (UG / DG), and says so.
- **MDE security settings management.** *Manage endpoint security policies in MDE*: devices not enrolled in Intune take assignments by device group only, and assignment filters do not apply to them. A policy whose `technologies` carry `microsoftSense` is flagged 🛰 when a user group or a filter is involved.
