# T28 MDE rollout — beta 10638

Date: 2026-09-29. T28 0.7. Promotion queue item 200.

## Why

10637 (another session) swapped T28's rail for top tabs and sub-tabs, and gave the reports a second left column. I reviewed it against 10636 in a mockup (`t28-reports-layout-mockup.html`):

- **The rail was better on four counts:**
  - every count is in view (the "Policies" tab showed none);
  - one click per pane (the tabs took two for six of the eleven);
  - it stays sticky while long tables scroll;
  - it is the same `ep-rail` as T13, T15, T20, T22 and T27.
- **10637's report workspace was better than the three stacked cards.** It keeps one saved preview, timestamps, "regenerate" notices, folding sections and one Export menu.

**Mihai:** "I think the other layout was better, but only the reports layout needed adjustment." He picked **option A — the reports live in the rail**.

## Change

| Before (10637) | After (10638) |
| --- | --- |
| Top tabs and sub-tabs (`.mr-tabs`, `.mr-subtabs`) | The rail again (`.ep-wrap` / `.ep-rail`), with a count on every pane |
| A second left column inside 📑 with three report buttons | 📑 Reports has three child nodes in the rail: 📋 Assignments, 🧾 Deployment configuration, ⚔️ Conflict check |
| Report state only visible inside the pane | Each node shows its state: *not generated*, *generated HH:MM*, *regenerate* (red), or for the conflict check *N to act · HH:MM* (red when N > 0). The parent shows *N of 3*. |
| The preview shared the width with the selector | The preview has the whole main column |
| "Generate report" on a generated report | "↻ Generate again" |
| `?.` in `focusOn` and `reportPreview` | Plain checks (house rule) |
| Tile chip `tag updated` UPDATED (unstyled class; production language) | `tag new` NEW, as the other beta tools |
| "About this tool" said "How it works under Settings" | "❓ How it works in the rail" |

**Kept from 10637:**

- the compact header, with "About this tool" folded and one "Rollout export ▾" menu;
- the saved-report preview (the exact exported HTML, folded into sections);
- the timestamps and stale or incomplete-read notices;
- a failed fresh check keeps the old report.

The child nodes are always shown, not only while 📑 is open. That keeps one click per report and the state at a glance, which were the reasons for going back to the rail.

**Keyboard.** Enter or Space on a report node opens its report. A `data-mrpane` link inside the main column ("Open Conflicts →") is left to its own click, so it no longer fires twice.

## Fixes found in the browser

- **The main column ran off-screen at 390px.** `.ep-wrap` stacks at 900px with `align-items:flex-start`, so the main column took its content's width (850px). T28's `.ep-main` now stretches.
  - The other rail tools share that rule and were not touched in this build. It is worth a look there.
- **Coverage headers broke mid-word** ("Exclusio / n group", "America / s"). Headers in the report preview now wrap between words. The table still scrolls in its own region.

## Validation

- **Tracked suites: all 16 pass.** `mderollout/screen` has 126 checks (+5):
  - the three report nodes sit right under 📑 and there are no tabs;
  - every pane keeps its count;
  - Enter opens a report node;
  - the conflict node reads "N to act" in red;
  - Assignments turns "regenerate" after a fresh check.
- **Scratch suites:** unchanged against the baseline. `sidenav-tests` was already red before this build (7 failing, before and after).
- **Real browser** (Chromium, demo): generated Assignments from its node, ran a conflict check, and saw Assignments turn "regenerate".
  - 1440px, light and dark: the page does not scroll sideways.
  - 390px: the page width equals the screen, the rail stacks above the report, and wide tables scroll inside their region.
  - No page errors.
