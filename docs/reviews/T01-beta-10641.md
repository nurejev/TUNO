# T01 masked policy values — beta 10641

Date: 2026-09-30. T01 1.0.76.

## Cause

Mihai's read diagnostic (captured on build 10638) for *Win - SEC - Device Security - D - AppLocker (Enforced) - R27.1 - V4.0.2*: all four AppLocker collections (StoreApps, EXE, MSI, Script) came back as `"****"` with `isEncrypted: false`, `decrypted: false`.

`Graph.hydrateOmaSettings` only fetched a value when it was empty, or when `forceEncrypted` was set **and** `isEncrypted` was true. A masked value with the flag false met neither condition. So the reader never made the single-profile re-read or the `getOmaSettingPlainTextValue` call, and passed `****` to `DOMParser`. The error then told the user to check the profile's XML in Intune, but there was nothing wrong with the profile.

## Change

- `js/graph.js`: new `isMaskedOmaValue` (a value made only of asterisks). `hydrateOmaSettings` now treats a masked value as unread, whatever `isEncrypted` says: single-profile re-read for the missing `secretReferenceValueId`, then one plaintext read per setting. If there is still no reference after the re-read, the setting gets `_masked` and a `_decryptError` that says so, and is listed in `errors`.
- `js/applocker.js`: `appLockerSettingDocument` refuses a masked value with a mask message before it reaches the XML parser. Read diagnostic schema 2 adds `masked`, `hasSecretReference` (boolean only, the reference itself is still never exported) and `readError`.
- `js/backup.js`: masked settings are included in the hydration filter, so a backup no longer archives `****` as the value. `_masked` is stripped along with the other hydration marks.

## Validation

- `npm test`: all 17 suites pass, **1369 assertions**. Six new audit-workflow checks (53 total) cover the mask with `isEncrypted: false` (one re-read, one plaintext read per collection, the profile opens with its rules, no diagnostic), the helper's edge cases, and a mask with no reference (mask message, never "not valid XML", no plaintext call, schema 2 fields). The new block throws on the 10640 code.
- Supplemental: `check-script-versions` 119/119. `graph-read-tests` 245/257 and `t01-xml-tests` 38/40 give the same counts on HEAD without this change (failures that already existed, not caused by this build).
- Syntax check passes on every changed JS file. Script changes are release stamps only.
