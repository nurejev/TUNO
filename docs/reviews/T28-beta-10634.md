## Why the device group is user-derived and assigned

Mihai's 29-09 run of `Compare-UserDeviceCountryGroups.ps1` checked the extensionAttribute-based `PVM-DG-CORP-AAD-W10-MEM-*` groups. It found **2,561 devices missing** from them and **2,933 in the wrong one**.

The Intune primary user is what decides. It is the script's own `-DeviceSource Intune` join:

1. `managedDevices.userId`
2. → `azureADDeviceId`
3. → the Entra device object.

An assigned group goes stale, so the pane shows every time it is read:

- the devices a group is missing;
- the devices whose primary user left the country.

## The model

| Group | Holds | Nested in |
| --- | --- | --- |
| `PVM-UG-CORP-MEM-USERS-<xx>` (exists, dynamic) | the country's users | `PVM-UG-MDE-WAVE-<region>` |
| `INT-SG-D-<ISO3>` (new, assigned, owner: the admin) | the Windows devices of those users | `PVM-DG-MDE-WAVE-<region>` |

Naming:

- ISO2 becomes ISO3.
- Overrides: `POL-Warszawa` → `POL-WAW`, `POL-SKARB` → `POL-SKARB`, `UAE` → `ARE`.
- Both tables can be edited under ⚙️.

Groups that have the prefix but are not in the table are listed and never nested. Of Mihai's 59 prefix groups, 20 are outside the table. `NL-Breda`, `IN-UP-Shortcut` and `IT-SELECTION` are flagged as overlaps.

## Microsoft Learn

- **Graph, Add members.**
  - At most 20 members per `PATCH members@odata.bind`.
  - A new group can answer "don't exist" while it replicates, so retry after a delay.
- **Intune, Performance recommendations for grouping and targeting.** "Don't make large group nesting changes all at once." The pane therefore works per wave and per country, and warns when a nest adds more than 500 members.
- **Entra, Manage groups.**
  - Security groups can be nested.
  - A dynamic group can be a member of an assigned group.
  - Groups cannot be added to a role-assignable group. The wave groups are not role-assignable.

## Writes

All writes use `Group.ReadWrite.All`, the scope T22 and the wave create already ask for, and all go through the run ledger:

- **Create:** `createWave`'s payload, with the admin as owner.
- **Fill:**
  - 20 per PATCH.
  - A chunk refused because one member is already in goes one by one, and the members already in count as done.
  - A "not replicated yet" answer is retried three times, with a growing pause.
- **Remove:**
  - Only when ticked.
  - Needs REMOVE typed to confirm.
- **Nest / take out:** `members/$ref`.

Every step is read back. Each run records what it did, and 📜 plans the exact undo from that record. Groups the run created are left in place, and the undo plan says so.
