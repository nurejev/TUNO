## Reports (new `js/mdereports.js`, 📑 pane)

Each report is a self-contained, printable HTML page (open it in a tab, or download it) plus a CSV. Every value is escaped.

| Report | Built from | What it says |
| --- | --- | --- |
| 📋 Assignments | the current read | Every in-scope policy's targets, each with its group kind, member count, filter and role in the rollout (wave, exclusion group, country group, device group).<br>A **coverage matrix**: per policy and per region, which wave is included (+D / +U) or excluded (⊘), plus the exclusion group.<br>New policies in no wave, and old policies that do not exclude a wave the new set includes, are named. |
| 🧾 Deployment configuration | current read + wave members (read if needed) + owners (read) | The rules; the wave and exclusion groups with their owners; the wave members per country; every new policy's settings (names from the definitions) and assignments; the old policies' retirement verdict; out of scope; this session's changes. The CSV has one row per setting. |
| ⚔️ Conflict check | a **fresh** read (`run(false)`: policies, wave groups, kinds, setting names) | The counts, then every collision grouped by old policy with the values on each side, the reach and the fix.<br>Each check is kept for the session; the next one says what moved (no longer needs action / new).<br>The rail counts what is left to act on. |

## Wave names: INT-SG-D-WAVE-* / INT-SG-U-WAVE-*

- **Defaults.** The wave prefixes are now `INT-SG-D-WAVE-` (device) and `INT-SG-U-WAVE-` (user).
- **Saved configs.** A config saved in the browser with the old default prefixes moves to the new ones: those prefixes were inherited, never chosen. A prefix typed by hand stays.
- **The old names are still looked up.** `renameFrom` holds the old defaults plus any prefix changed under ⚙️. Every wave carries its `oldNames`, and the group lookup asks for both.
- **The 🌊 pane:**
  - A wave that exists only under an old name shows as **old name** and gets a rename tick.
  - The rename has its own confirm tick, separate from Create.
  - When both a new-named and an old-named group exist, the old one is named and left alone.
- **`renameGroup`:**
  1. Refuses if another group already has the new name.
  2. PATCHes `displayName` and `mailNickname`. The nickname follows T22's rule; if the tenant refuses it, the name is changed alone and the ledger says so.
  3. Reads the group back.
- **Impact.** The object id does not change, so every policy assignment and every nesting is untouched; Intune simply shows the new name. 📜 renames it back.
- **Exclusion groups.** They keep their names (`PVM-DG/UG-MDE-Exclusion`); they can be changed under ⚙️.
- **Kind by name.** A U or D segment in a group name reads as user or device (`INT-SG-U-…`, `INT-SG-D-…`).
- **Wave members.** The `INT-SG-D-` device-group read skips the `-WAVE-` groups.
