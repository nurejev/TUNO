## New lifecycle checks

Automatic source loading is serial and permission-aware. Missing permission shows an explicit Connect action. Each source is attempted once per refresh, preventing error retry loops. Reopening keeps the read. Background work does not start while a plan or write is active. Navigation during loading is allowed, and asynchronous source/report responses check their project epoch before updating tenant state.

Reports build from available evidence when selected. Their freshness includes policy, rules, membership, write count and the applicable landing/device timestamp. Error or partial source data is shown as a gap. A policy-result count is labelled as a member × policy count, not a unique-device count.
